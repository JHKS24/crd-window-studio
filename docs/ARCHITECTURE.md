# Architecture and boundaries

## Components

`CRDWindowStudio` is the SwiftUI settings and preview process. `CRDSettingsCore` validates configuration, writes it atomically and exposes a Foundation model. The settings app invokes `companionctl.py` through a process/JSON boundary. That controller prepares and manages only `local.crdwindow.host` and its temporary permission and restoration jobs in the current user's launchd domain.

`OverlayMain.mm` is an independent AppKit agent. It uses NSWorkspace for application lifecycle, AXObserver for the identified sharing window, and directory vnode events for configuration changes. It owns the replacement panel and menu bar. It does not run inside the Google process, link its libraries, replace its executable, or manage its broker/service. The Google host is required only for real-session operation.

The controller writes successful results as JSON on stdout. Failures use one JSON object on stderr: `{"error":"accessibility_required","message":"diagnostic detail"}` with exit status 1 (invalid arguments use 2). The app localizes the stable `error` code and keeps `message` as diagnostics. Install records and `status` also expose optional `errorCode` and `cleanupErrorCode` beside their existing messages, so an action failure and incomplete cleanup can both be explained. Records and runtime reports may omit these fields.

Explicit `status` requests use documented `notify(3)` IPC, addressed by user ID and the verified helper job PID. `notifyutil` registers for one acknowledgement before posting; the helper coalesces requests and acknowledges after writing its runtime status. The controller waits at most two seconds and never reports confirmed readiness on acknowledgement failure. `runtime.refreshConfirmed` is true/false for a running helper and null when none is running. Permission checks post the same request without waiting (`runtimeRefreshRequested` in their result). Opening the helper menu also rechecks trust. There is no idle permission poll or dependency on a private TCC notification.

## Targeting and original visibility

The host path, current-user process UID and Google publisher signature are verified. The agent then validates the expected Accessibility window/control structure. It changes the original host application's AXHidden state, not a generic arbitrary window's state. The separate panel supplies the configured appearance. Detection ambiguity and unsupported structures must preserve or attempt to restore the original UI.

The controller's Google requirement includes the exact host identifier `com.google.chromeremotedesktop.me2me-host` as well as its publisher. For our helper, preparation records the executable's SHA-256 and designated requirement after signing and verification. Before executing an installed helper, the controller checks that fingerprint and verifies the bundle against the recorded requirement and `local.crdwindow.host`. Recovery therefore accepts the recorded older build after an app update, not an arbitrary app that merely uses the same identifier. This guards against accidental or partial replacement; the user-writable receipt is not a security boundary against an attacker who can also rewrite that receipt.

Stop Sharing is only forwarded after a user action and current target/session-token validation. Previews and fixtures cannot disconnect a session. Native menus close on outside click, Escape or deactivation and remove temporary event monitors on completion.

Presses on the custom window go through the helper's own tracking loop: a press that moves less than 3 pt is a click, a longer drag moves the window with `setFrameOrigin` (clamped to the visible frame when constrainToScreen is on) and is the only source of user geometry besides the resize grip. The panel is never Resizable or server-movable, and any other size change is reverted without saving. The dot reveals Stop after the double-click's mouse-up; a double-click on the capsule outside Stop plus a 6 pt margin shrinks it, and Stop itself only accepts a fresh single click. Every non-Stop gesture (its down and its mouse-up, including one the tracking loop consumed), every context menu, and any change that moves or shows the inline Stop keeps the Stop gate closed for a double-click interval, so Stop needs a separate later click in the capsule and in the bar. A burst of system resizes keeps one trailing correction. Presets are applied with a placement normalized for the display they will use, in the same locked write, by both the helper and the settings app; the preview window saves only moves and resizes made by the user's own drag. `presets.json` is written only by the settings app, atomically under `config.json.lock`; the helper reads it for its Presets submenu and ignores an unreadable file. Its capsule and fallback menu reject the continuing click sequence, including clicks whose count resets across windows. A new click after the system multi-click interval, or an explicit menu keyboard selection, is required; Reduced Motion uses the same gate. The button is disarmed while opening and closing. Choosing Open Settings suppresses the usual previous-app activation after menu dismissal.

## Configuration and geometry

The schema in `Sources/CRDSettingsCore/Resources/SettingsSchema.json` is canonical. Generated C++ headers and the Windows schema copy must stay in sync. Settings offsets use the selected screen's visible-frame top-left; AppKit runtime frames use global screen points with a bottom-left origin. Logs label these coordinate spaces.

The two display modes are `custom` and `original`. First run and reset select `custom`, displaying the styled sharing window; a saved `hidden` mode loads as `custom`. An invalid existing configuration blocks edits and ordinary reset; explicit recreation first backs up its exact bytes beside the file. A previously loaded file that disappears keeps the last settings and pending edits until it returns.

The dot's diameter and background padding are independent. Expansion uses a temporary capsule panel and moving dot while leaving saved geometry unchanged. Closing restores the original frame. The menu bar is owned by the helper so it remains available when the settings process exits.

Only user drag/resize events mark helper geometry dirty. Delayed saves and shutdown use the captured user frame, not a later system-moved frame. Programmatic repositions, screen changes and external configuration reloads invalidate pending geometry saves. A shutdown without unsaved user geometry does not rewrite placement.

## Failure and compatibility limits

Normal shutdown, original-mode selection and handled errors restore the original hidden state. Unexpected exit is covered by the helper's own launchd restart policy, but immediate recovery cannot be guaranteed when permission is revoked, the host changes, or the helper cannot restart. Use the documented recovery path and retain access to Google's original controls.

A failed owned unhide sets `runtime.restorationBlocked=true`, keeps the journal and makes readiness false. `restorationPending` alone is not an error: it is also true while the helper intentionally owns a hidden original. After `cleanup_failed`, an explicit `restore` retry can run the retained, signature-verified helper with `--crd-restore-only` in `local.crdwindow.restoreprobe`. This one-shot job has no KeepAlive, overlay, observers or permission prompt. It tries only the journaled unhide, or clears a dead/replaced target on ESRCH/different process birth. Unknown liveness never clears the obligation. The controller allows ten seconds for a result and reserves five seconds for cleanup; it checks the result, cleared journal, unloaded job and exited process before archiving. Failures retain the helper and report `restoration_unconfirmed`.

Install records without a helper fingerprint support normal `restore`, which stops the existing job without launching a probe. If restoration-only execution is needed, the controller first verifies the retained helper against the certificate requirement of the trusted current build, then records its fingerprint. Keep the same signing certificate when upgrading. An unrecorded ad hoc helper cannot be authenticated this way and is retained with `helper_verification_failed`; it is not executed on an identifier-only check. Recorded ad hoc helpers can recover across updates using their stored fingerprint.

Host version numbers are not pinned; structural compatibility is still required. Each new CRD/macOS release needs actual-session testing. The source build's minimum macOS target and universal architectures do not certify all combinations. No Google binary is included in source or app packages. `reference/` files are attribution/research material only and are not build inputs.
